# PostgreSQL & Prisma ORM Skill

This skill guides database design, maintenance, and migrations for **PostgreSQL 16** using **Prisma ORM**.

---

## 🚀 Quick Reference Commands

### Docker Compose Database Orchestration (Project Root)
```bash
# Start PostgreSQL 16 and Adminer in background
docker compose up -d postgres adminer

# Check container status and health
docker compose ps

# View PostgreSQL container logs
docker compose logs -f postgres

# Stop database services
docker compose stop postgres adminer
```

### Prisma ORM Commands (Run inside `backend/`)
```bash
# Generate Prisma Client TypeScript types after editing schema.prisma
npm run prisma:generate

# Create and apply a new migration during development
npm run prisma:migrate -- --name <migration_name>

# Apply pending migrations in staging/production (Cloud Run / CI)
npm run prisma:migrate:deploy

# Run the database seeder (prisma/seed.ts)
npm run prisma:seed

# Open Prisma Studio web GUI (http://localhost:5555)
npm run prisma:studio
```

## 🏛 Core Database & Modeling Rules

1. **Naming Conventions & Mappings**:
   - **Prisma Models**: PascalCase (e.g., `User`, `Project`, `AuditLog`).
   - **Database Tables**: Plural snake_case using `@@map("...")` (e.g., `@@map("users")`, `@@map("projects")`).
   - **Database Columns**: snake_case for PostgreSQL columns using `@map("...")` (e.g., `createdAt DateTime @default(now()) @map("created_at")`).
   - **Relations**: CamelCase in Prisma (e.g., `owner User @relation(...)`), Foreign Key columns with `_id` suffix (e.g., `ownerId String @map("owner_id")`).

2. **Primary Keys & Types**:
   - Use UUID primary keys for all entities to prevent ID enumeration:
     ```prisma
     id String @id @default(uuid())
     ```
   - Standard audit timestamps on every table:
     ```prisma
     createdAt DateTime @default(now()) @map("created_at")
     updatedAt DateTime @updatedAt @map("updated_at")
     ```

3. **Migration Integrity**:
   - Never manually edit applied migration files in `backend/prisma/migrations/`.
   - In development, execute `npm run prisma:migrate -- --name <descriptive_name>`.
   - In production or CI/CD pipelines (e.g. Cloud Build), always use `prisma migrate deploy`.

4. **Connection Pooling & Cloud SQL**:
   - Local: Connects via standard TCP socket (`postgresql://postgres:postgres@localhost:5432/el_dugout_ve?schema=public`).
   - Cloud Run (GCP): Connects to Cloud SQL via Unix socket:
     `postgresql://<user>:<pass>@localhost/<dbname>?host=/cloudsql/<project>:<region>:<instance>&schema=public`

5. **Query Optimization**:
   - Use `select` or `omit` to avoid fetching unnecessary large columns.
   - Avoid N+1 query patterns: use Prisma `include` carefully or join queries with explicit batching.
   - Add indices (`@@index([column])`) for columns frequently used in `where` filters or foreign key joins.

```text
backend/prisma/
├── migrations/                # Versioned SQL migration files generated by Prisma
│   └── 2025..._init/
│       └── migration.sql

└── seed.ts                    # Idempotent seed script for local development
```

## 🛠 Step-by-Step Schema Evolution Procedure

### Step 1: Modify `backend/prisma/schema.prisma`
Add or update models, relations, or enums. Ensure all mappings use `@map` and `@@map`.

### Step 2: Create and Apply Migration
```bash
cd backend
npm run prisma:migrate -- --name add_new_entity
```
Prisma will generate the SQL file in `backend/prisma/migrations/` and apply it to the running PostgreSQL database.

### Step 3: Regenerate Prisma Client
```bash
npm run prisma:generate
```
This updates TypeScript typings in `node_modules/@prisma/client`.

### Step 4: Update Seed Script (Optional)
If sample data is needed for local development, update `backend/prisma/seed.ts` and test with:
```bash
npm run prisma:seed
```

See [references/patterns.md](./references/patterns.md) for relation examples and migration troubleshooting.
